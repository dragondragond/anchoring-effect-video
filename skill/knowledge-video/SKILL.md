# 知识大赏短视频

这类视频放完一首 BGM 就结束（约 2 分半）：画面讲故事，底部一行字幕代替旁白，左上角年份、右上角出处，结尾一句金句。已经做过的两期是最好的参照：

- `02/simpson`：辛普森悖论（肾结石 → 伯克利 → 降压药 → 因果 → AI）
- `02/anchoring`：锚定效应（轮盘 → 法官 → 调整不足 → 谈判 → AI）

一期从定题到成片大约 25～30 分钟，其中渲染只要一分半。所以与其让用户先审文字稿，不如直接做出成片再按反馈改。

## 需要的输入

- **主题**：用户定。没定的话，按 `references/format.md` 第 2 节的标准给 4～6 个候选
- **BGM**：mp3。换了 BGM 就要重新分析节拍
- **署名**：默认「LIGHT聊AI」
- **参考爆款**（可选）：拆解一次就够，结论已写在 `references/format.md`

## 流程

### 1. 拆解素材（第一次做，或换了 BGM / 参考视频时）

```bash
ffmpeg -i ref.mp4 -vf "fps=1/5,scale=480:-1,tile=5x6" -frames:v 1 sheet.jpg      # 参考视频总览
node scripts/check_reference_audio.mjs bgm.mp3 ref1.mp4 ref2.mp4                 # 是否同一首 BGM、有没有旁白
node scripts/analyze_bgm.mjs bgm.mp3                                              # BPM、首拍、每两小节能量、段落
```

段落表决定叙事节奏：标题落在低音进入那一小节，转折放在没有低音的回落段，金句放在最后的高点。

### 2. 查资料，核实每一个数字

用 WebSearch / WebFetch 找到原始研究。规则：

- **每个上屏的数字都要有出处**，记在分镜脚本里，写清楚来自原文还是二手资料
- **原文看不到、只有一个二手来源的数字，不上屏**，只做定性表述；连定性都撑不住就删掉这个案例
- **取整要说明来源**（例：法官刑期 5 和 8 个月是 Kahneman 的取整，原文是 5.28 和 7.81 个月）
- **区分统计范围**（例：伯克利 44% 对 35% 是全校数据，「六个院系里四个女生更高」是最大六个院系）
- **转述不加引号**；论文没点名的模型不要点名；思想实验要说明是思想实验
- **示意性的画面**（比如点的分布、聊天窗口）在角标或分镜脚本里注明
- **推论性的建议**（如「问 AI 时别先给数字」）在分镜脚本里注明是推论

### 3. 写字幕稿和分镜

按 `references/format.md` 写，结果存进 `分镜脚本.md`（模板里有骨架）：一句话核心、金句、音乐段落表、每条字幕（小节时间 + 文字 + 画面）、数据与出处。

写完对照这几条自查，它们都是用户实际指出过的问题：

- 钩子让观众自己作答，用真实数据，最后一句反转
- 第一个案例讲完，在高能段最高点点题：「这就是 X：一句话定义」
- 每个案例至少两条字幕，有铺垫 → 数据 → 结论；一闪而过的案例宁可删掉
- 案例之间有过渡词，几个案例之后有一句总结共同机制
- 对策具体、有依据，紧跟在它针对的场景后面；不要讲完 AI 又跳回早年的研究
- 数字单位统一，术语说人话
- 结尾回扣钩子的画面，片尾卡留约 5 秒

### 4. 新建工程，写画面

```bash
node scripts/new_episode.mjs --dir 02/<slug> --bgm <bgm.mp3> --title 主题 --en "ENGLISH TITLE" --out <主题>.mp4
```

会复制模板、生成 `src/music.js`、借用兄弟目录的 node_modules。然后：

1. `src/data.js`：填 `CONFIG`（标题、副标题、署名、金句、参考资料、封面文案）、`SUBS`、`CORNERS` 和本期数据
2. `src/scenes.js`：写本期场景，放进 `SCENES` 列表。引擎 API、通用组件和编排模式见 `references/engine.md`；需要具体写法时，读 `references/examples/` 里两期的场景代码（专用组件如轮盘、骰子、锚、法槌、2×2 表格、点阵变形都可以直接借）
3. `src/cover.js`：把 `coverHero()` 换成本期的核心视觉

画面上的几条硬要求：

- 每期一个核心视觉隐喻，物体在场景之间延续（标题碎成数据点，点再变成下一个案例里的人）
- 每两秒内都要有和内容相关的动作，停顿处补上计数、跳动、绳子拉扯、打字、思考中之类的动画
- 内容放在 y < 930，避开字幕
- 前一个场景先退，后一个再进；组件里的透明度只乘不赋值

### 5. 自检

按 `references/qa.md` 逐项做：总览图 → 全尺寸截图 → 转场拼图 → `scripts/motion_check.mjs` → 成片抽帧。发现问题就改，局部重渲。

### 6. 交付

- `node render.mjs --workers=6` 出片，复制到上一级目录：`<主题>_<署名>.mp4`
- `node cover.mjs` 出两张封面
- 更新 `分镜脚本.md` 和 README，删掉 `out/` 里的中间帧
- 用 SendUserFile 把成片发给用户，回复里说明：内容主线、哪些是示意 / 转述 / 推论、哪些数据只做了定性表述

## 用户反馈时

逐条确认问题在哪，说明原因再改；顺手扫一遍同类问题（比如用户指出一处画面静止，就跑 `motion_check.mjs` 找出所有静止段）。改完重新跑第 5 步，再交付。

## 参考文件

| 文件 | 什么时候读 |
|---|---|
| `references/format.md` | 选题、写字幕稿和分镜时（爆款拆解、结构模板、字幕规则、案例和对策怎么放、视觉语言） |
| `references/engine.md` | 写画面代码时（API、组件、编排模式、技术坑、渲染命令） |
| `references/qa.md` | 自检和交付前 |
| `references/examples/simpson/`、`references/examples/anchoring/` | 想看一整期是怎么编排的、或要借专用组件时（storyboard.md + data.js + 场景代码） |
| `assets/template/` | 新工程的模板（一般通过 `new_episode.mjs` 使用） |
| `scripts/` | `analyze_bgm.mjs`、`check_reference_audio.mjs`、`new_episode.mjs`、`motion_check.mjs` |

依赖：Node.js、Google Chrome（默认路径 `/Applications/Google Chrome.app`，否则设 `CHROME_PATH`）、ffmpeg / ffprobe、macOS 自带的 Songti SC 字体。
